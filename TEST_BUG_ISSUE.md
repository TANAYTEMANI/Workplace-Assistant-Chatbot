# Bug: Chroma indexing keeps only one chunk per page

## Summary
After rebuilding the vector store with `create_database.py`, retrieval quality drops significantly because only one chunk per PDF page is preserved in Chroma.

## Observed behavior
- Running `python create_database.py --reset` succeeds.
- But the number of indexed documents is much lower than expected.
- Queries that should match text from later chunks on the same page often fail.

## Expected behavior
Each chunk generated by `split_documents()` should have a unique ID, including chunk index, so all chunks from a page are stored.

## Reproduction
1. Put at least one long PDF in `pdf_data/` (enough to create multiple chunks per page).
2. Run:
   ```bash
   python create_database.py --reset
   ```
3. Inspect retrieval with:
   ```bash
   python policy_app.py "Ask something from the second half of a long page"
   ```
4. You will often miss content that should be retrievable.

## Suspected root cause
`calculate_chunk_ids()` is generating non-unique IDs for chunks on the same page.

## Fix direction
- Ensure chunk IDs include:
  - source
  - page
  - chunk index
- Example shape:
  - `path/to/file.pdf:6:2`
